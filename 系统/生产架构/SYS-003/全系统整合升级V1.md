# SYS-003｜全系统整合升级 V1

## 目标
把SYS-002的单篇生产强项升级为长期账号系统。运行版采用16个正式生产AI + 2个条件AI，保留商品/SKU、PERSONA、资产身份证、三道图片审核、局部返修和R01独占正式权限。

## 新增四块
1. ACCOUNT_STRATEGY_LOCK：锁长期账号定位、目标女性人群、内容支柱与比例、人物/产品图比例、视觉基调、标题/语言风格、商业内容比例、阶段目标和禁止偏离项。
2. VOICE_LOCK：锁账号语言人格。文案每篇都必须读取，不允许“脸是同一个人，文字每天换一个人”。
3. R15数据分析与实验：R14只采集真实数据，R15做基线、判断、实验。
4. R16账号策略与增长规划：初始化、每10篇、定位漂移、粉丝阶段变化、开始商业化或R15发现路线失效时才运行。

## 合规
R13升级为内容真实性与平台合规审核。必须读取当前有效COMPLIANCE_SNAPSHOT。快照过期或关键规则无法核实时进入BLOCKED，不允许用旧记忆放行。
公开正文不需要机械写后台生产说明，但绝不能把这一点解释为规避法律或平台要求的AI生成内容标识、广告/商业披露等功能。

## 长期循环
R16策略LOCK → 02/03机会发现 → 04商品事实 → 05商品锁 → 06策划 → 07文案/VOICE → 08视觉 → 09图片 → 10/11/12三审 → 13真实性+合规 → 01 CONTENT LOCK → 14发布/社群/原始数据 → 15分析实验 → 必要时16策略复盘 → 下一篇。

## 用户最少操作
用户只在这些节点必须参与：提供必要图片/账号真实信息；对预算/商务/重大策略做决定；实际发布；普通聊天模式下在24h/72h/7d窗口再次触发数据采集。其余角色通过GitHub明确任务、指针和交付恢复，不要求用户手工计算SHA或重复上传已可稳定引用的资料。

## 版本原则
SYS-002历史文件保留用于审计。SYS-003是新的运行架构版本，由根入口切换。旧LOCK不覆盖，新LOCK用新版本和supersedes。
